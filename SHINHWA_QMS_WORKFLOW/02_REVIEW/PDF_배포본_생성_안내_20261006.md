# PDF·배포본 생성 안내 (2026-10-06)

## 1. 현재 상태와 이 환경의 한계
- `05_FINAL/RELEASED` 의 릴리스 3건(공식양식 SH-FM-066~096 Rev00, SH-FM-122 Rev00, 현장작성양식 SH-FM-101~121 Rev03)에는 PDF·배포본이 없다(`05_FINAL/PDF`, `05_FINAL/배포본` 폴더도 비어 있음, 배포목록의 PDF·배포본 열이 `X`).
- 이 클라우드 환경에는 `soffice` 실행 파일은 있으나 Writer·Calc 구성요소가 없어 docx·xlsx 를 열 수 없다(txt·xlsx·docx 변환 시험 모두 `source file could not be loaded`). 따라서 **여기서는 PDF 를 만들 수 없다** — LibreOffice 가 설치된 PC 에서 해야 한다.
- 스크립트의 PDF 변환(`to_pdf`)은 `finalize`(승인완료 → 05_FINAL) 단계에서만 동작한다. **별도의 '기존 릴리스에 PDF 추가' 명령은 없다.**

## 2. 언제 만드는 것이 맞나 (순서)
- 지금 있는 릴리스 3건은 모두 **개정 중인 문서**다(공식양식·SH-FM-122 는 날짜 정리 수정본이 승인대기, 현장작성양식은 내용 개정 수정본4 가 승인대기). 이전 릴리스본에 PDF 를 만들면 곧 대체될 옛 날짜·옛 내용(보존 5년 등)이 배포본이 된다.
- 따라서 **새 수정본을 승인·`finalize` 할 때 PDF·배포본이 자동으로 함께 생성되게 하는 것**이 맞다. 승인 대상: SH-QP-018 수정본7(Word→PDF), 현장작성양식 수정본4(21시트 xlsx→PDF), 공식양식 수정본, SH-FM-122 수정본2(SH-FM-122 는 결재란 '승인' 성명·서명·일자부터 채워야 함). 승인은 사용자의 지시와 실제 승인 확인 후에만 한다.

## 3. PC 에서 하는 방법 (Windows 기준)
1. **LibreOffice 설치**(무료). 설치 후 `C:\Program Files\LibreOffice\program` 을 PATH 에 추가하고 새 명령 창에서 `soffice --version` 이 나오는지 확인.
2. **저장소 전체 받기**: 가벼운 ZIP(`SHINHWA_QMS_LIGHT.zip`)은 `finalize` 를 쓸 수 없다. `git config --global core.longpaths true` 후 짧은 경로(예: `C:\q`)에 저장소를 clone 한다(경로 260자 문제 때문).
3. 환경 준비(명령은 한 줄씩):
   - `cd SHINHWA_QMS_WORKFLOW`
   - `pip install -r requirements.txt`
   - `set PYTHONUTF8=1` , `chcp 65001`
4. 상태 확인: `python scripts/qms_workflow.py status` — 승인대기 문서와 Gate 상태.
5. **(사람의 승인 후에만)** `python scripts/qms_workflow.py approve <파일명>` → `sign <파일명>` → `finalize`. `finalize` 가 Gate 를 재확인하고 `05_FINAL/RELEASED/<문서번호>/Rev<NN>/` 에 문서·PDF·MANIFEST 를 저장하고 `05_FINAL/배포본/` 에 `…_배포본_날짜.pdf` 를 만든다. 같은 Rev.03 이면 새 폴더는 `Rev03_v2` 로 생기고 이전 폴더는 `06_HISTORY/이전버전/` 으로 이동(삭제 아님)한다.
6. 확인: `python scripts/qms_workflow.py integrity`(SHA-256), `finalreport`. 생성된 PDF 를 열어 쪽 수·잘림(A4 세로, 시트 1개 = 1쪽 설정), 머리글·바닥글, 한글 깨짐을 눈으로 확인한다.
7. 결과(PDF·배포본·로그)를 커밋·푸시한다(브랜치 `claude/shinhwa-qms-workflow-54alyc`).

## 4. 알아둘 점
- 워크북(현장작성양식 21시트, 공식양식 9시트)은 **PDF 한 파일에 시트가 모두 들어간다.** 현장 배포를 양식별 PDF 로 하려면 별도 처리가 필요하다(원하면 시트별 분리 PDF 기능을 추가할 수 있음).
- `finalize` 는 `승인완료`(사람의 `sign`)가 없으면 배포본을 만들지 않는다. 승인 전 문서의 PDF 는 배포본이 아니다.
- PC 에서 변환이 실패하면 `finalize` 는 PDF 없이 릴리스하고 로그에 '변환 실패(배포본 없음)'을 남긴다 → soffice PATH 와 엑셀·워드 파일이 다른 프로그램에서 열려 있지 않은지 확인.
